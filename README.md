# ARETE — Fitness Platform (Flutter)

A member-facing training app and trainer console, built as **one Flutter codebase** targeting
**Android first, iOS next**. This repository is **Phase 1**.

> Design proposal (screens, functions, roadmap): see the approved visual proposal that scoped this work.

---

## Phase 1 scope

| # | Module | Status in this slice |
|---|--------|----------------------|
| 01 | **Member Profile** | ✅ Built end-to-end (profile, edit, settings, membership, badges) |
| 02 | **Health Assessment & Starter Plans** | ✅ Built (questionnaire, PAR-Q, matched plan + alternatives) |
| 03 | **Workout Execution** | ✅ Built (today's session, set logging, rest timer, PR detection, summary) |
| 04 | **Progress Tracking** | ✅ Built (weight trend, volume, PRs, measurements, photos) |
| 05 | **Trainer Management** | ✅ Member Coach tab (chat, plan hand-off, booking) + trainer roster |

The first vertical slice ships the **Member Profile module end-to-end** on top of the full app
foundation (design system, navigation, models, state, **role switching** between Member and Trainer).
The remaining tabs are clearly-labelled "coming next" placeholders so the roadmap stays visible in
the running app.

Decisions locked for Phase 1:

- **Framework:** Flutter (one codebase → Android + iOS)
- **Backend:** Local-first — repositories persist to on-device storage; swap for Firebase/REST later with no UI change
- **Auth:** Email/password sign-up & sign-in with a persisted session (local, hashed passwords). `AuthRepository` is the seam for a real backend.
- **Roles:** One app with Member ↔ Trainer role switching (see **Settings → Viewing as**)

## Running the app

Requires Flutter **3.27+** (Dart 3.6+).

```bash
flutter pub get
flutter run                 # any connected Android device / emulator
```

Other useful commands:

```bash
flutter analyze            # static analysis / lints
flutter test               # run the widget tests
flutter build apk          # Android release build
```

> The native `android/` and `ios/` folders are generated by Flutter. If they are not present after
> cloning, run `flutter create .` in the project root once to add the platform runners, then
> `flutter run`.

## Architecture

Layered, dependency-inverted so the UI never knows where data comes from:

```
UI (features/*)  →  State (state/*)  →  Repository (interface)  →  Mock / API impl
     widgets          ChangeNotifier      ProfileRepository        MockProfileRepository
```

```
lib/
├── main.dart                     # composition root — wires repo + providers
├── app/arete_app.dart            # MaterialApp, theme, home shell
├── core/
│   ├── constants/enums.dart      # domain enums (role, goal, tier, units, …)
│   └── theme/                    # colors, typography, spacing, ThemeData
├── shared/widgets/               # design-system components (card, pill, stat tile, …)
├── data/
│   ├── models/                   # Member, BodyMetrics, Membership, Trainer
│   ├── mock/mock_data.dart       # seed data
│   └── repositories/             # ProfileRepository + MockProfileRepository
├── state/                        # SessionController, ProfileController, TrainerController
└── features/
    ├── shell/app_shell.dart      # bottom-nav scaffold, role-aware tabs
    ├── profile/                  # Member Profile module (built)
    └── placeholder/              # coming-soon screens for later modules
```

### Swapping in a real backend

Implement `ProfileRepository` (e.g. `ApiProfileRepository`) and change the single line in
`main.dart`:

```dart
final ProfileRepository profileRepository = ApiProfileRepository(...); // was MockProfileRepository()
```

No screen or widget needs to change.

## Design system

Brand tokens live in `lib/core/theme/`. Ember (`#EF5A2A`) is the primary accent, Teal (`#10A596`)
the secondary/success accent. Light and dark themes are both defined via an `AppPalette`
`ThemeExtension`; access tokens in any widget with `context.palette` and text styles with
`context.textStyles`.
